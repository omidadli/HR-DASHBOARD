# سامانه مدیریت منابع انسانی کارا (Kara HRMS)
### سامانه بومی منابع انسانی ویژه بازار ایران با دستیار هوشمند استخدام، تقویم جلالی و موتور محاسباتی منطبق با قانون کار (پیکربندی سال‌های ۱۴۰۳ تا ۱۴۰۵)

---

## ۱. معرفی کلی سامانه
«کارا» یک سامانه یکپارچه برای مدیریت چرخه عمر سرمایه‌های انسانی در شرکت‌های ایرانی است:
- **پشتیبانی سراسری از زبان فارسی و چینش RTL** با تایپ‌فیس **وزیرمتن (Vazirmatn)**
- **تقویم و تاریخ‌نگار شمسی (جلالی)** با مبدل دقیق دوطرفه؛ تاریخ «امروز» در سمت سرور بر اساس منطقه زمانی **Asia/Tehran** محاسبه می‌شود و تمامی مهرهای زمانی (تردد، مرخصی، چک‌لیست، آموزش) از همان منبع واقعی گرفته می‌شوند — هیچ تاریخ ساختگی در خروجی‌ها وجود ندارد.
- **موتور قانون کار و تامین اجتماعی** (`server/statutory.ts`، `server/leave-service.ts`، `server/payroll-service.ts`):
  - مالیات پله‌ای حقوق با پیکربندی سالانه (۱۴۰۳، ۱۴۰۴، ۱۴۰۵) — تولید فیش فقط برای سال‌های پیکربندی‌شده مجاز است
  - حق اولاد مشروط به سابقه ۷۲۰ روزه بیمه (ماده ۸۶ تامین اجتماعی) و خارج از مبنای حق بیمه
  - عیدی با سقف قانونی (حداکثر معادل ۳ برابر حداقل دستمزد ماهانه سال)
  - مرخصی سالانه ۲۶ روز کاری (ماده ۶۴)، سقف انتقال ۹ روز (ماده ۶۶)، مرخصی ازدواج/فوت ۳ روز (ماده ۷۳)
  - اضافه‌کاری با ضریب ۱.۴ (ماده ۵۹) بر اساس رکوردهای واقعی تردد
  - چرخه حیات فیش: پیش‌نویس ← نهایی ← پرداخت‌شده با قفل دوره (دوره پرداخت‌شده غیرقابل بازمحاسبه است)
- **دستیار هوشمند ارزیابی و استخدام**: در صورت وجود کلید `GEMINI_API_KEY` از مدل‌های Gemini با Function Calling استفاده می‌شود؛ **در نبود کلید، سامانه وانمود به هوش مصنوعی نمی‌کند** — امتیازدهی محلی با برچسب صریح «موتور محلی (بدون Gemini)» (`aiAvailable: false`) انجام می‌شود، رزومه خالی با خطای ۴۰۰ رد می‌گردد و پیش‌نویس ایمیل «رد» فقط برای کارجوی مشخص تولید می‌شود.

> ⚠️ **شفافیت درباره وضعیت محصول:** گزارش کامل ممیزی محصول در `PRODUCT_BUG_REPORT.md` موجود است. تصمیم‌های کسب‌وکاری علامت‌گذاری‌شده (D1 تا D7) هنوز در انتظار تأیید مالک محصول هستند و فعلاً با پیش‌فرض‌های مستند پیاده‌سازی شده‌اند.

### معماری داده و ماندگاری
- **پایگاه‌داده واقعی متصل نیست.** وضعیت سامانه در حافظه نگه‌داری و به صورت اسنپ‌شات در `data/hrms-store.json` ذخیره می‌شود. فایل `prisma/schema.prisma` فقط مرجع طراحی است.
- هویت و نقش کاربر از طریق هدر `x-user-role` اعلام می‌شود و **سوییچر نقش صرفاً ابزار دمو است**؛ اما دامنه دسترسی (RBAC) سمت سرور اجرا می‌شود: نقش کارمند فقط داده خودش را می‌بیند، مدیر واحد فقط دپارتمان خود، و اقدامات حساس (تولید فیش، اتوماسیون، حذف) فقط برای نقش‌های مجاز. این مکانیزم برای استقرار واقعی نیازمند احراز هویت واقعی است.

## ۳. معرفی ماژول‌ها و سطوح دسترسی (RBAC)

سه سطح دسترسی وجود دارد که از طریق نوار بالای برنامه (دمو) قابل تغییر است و **سمت سرور نیز اعمال می‌شود**:
1. **مدیر ارشد منابع انسانی (HR Director)**: دسترسی کامل؛ تولید و نهایی‌سازی فیش، اجرای اتوماسیون‌ها، تأیید نهایی مرخصی‌ها، حذف رکوردها.
2. **مدیر واحد (Department Manager)**: فقط داده دپارتمان خود؛ مرحله اول تأیید مرخصی زیرمجموعه؛ بدون دسترسی به اتوماسیون و مالی شرکت.
3. **کارمند (Employee)**: فقط داده شخصی (فیش، تردد، مرخصی، چک‌لیست)؛ ثبت درخواست مرخصی با محدودیت سهمیه؛ بدون دسترسی به حقوق و کد ملی دیگران.

### وضعیت تفصیلی ماژول‌ها
- **ماژول ۱ — جذب و استخدام**: پایپ‌لاین کانبان با **قانون گذار واقعی** (پرش غیرمجاز بین مراحل با ۴۰۹ رد می‌شود؛ رسیدن به مرحله «استخدام» بدون ارزیابی تکمیل‌شده ممکن نیست). بارگذاری گروهی رزومه **فقط با فایل واقعی** کار می‌کند و متن رزومه‌ها به‌صورت واقعی در سمت کلاینت استخراج می‌شود (PDF/DOCX/TXT و آرشیو ZIP)؛ هر رزومه در لحظه بارگذاری توسط موتور ارزیابی (Gemini در صورت وجود کلید، وگرنه موتور محلیِ برچسب‌دار) امتیاز واقعی می‌گیرد — بدون امتیاز تصادفی و بدون هویت ساختگی. فایل‌های غیرقابل‌تجزیه (مثل اسکن تصویری) با دلیل گزارش و رد می‌شوند، نه جعل. مرحله کارجویان هرگز خودکار تغییر نمی‌کند (دسته‌بندی فقط پیشنهادی است). چت دستیار با حافظه مکالمه و برچسب شفاف منبع امتیاز.
- **ماژول ۲ — پرونده پرسنلی**: اعتبارسنجی کد ملی (checksum)، یکتایی کد ملی/ایمیل/شبا، ثبت سابقه واقعی تغییر حقوق، و **حذف با محافظت**: اگر سابقه قانونی (فیش، تردد، مرخصی) وجود داشته باشد حذف با ۴۰۹ مسدود می‌شود.
- **ماژول ۳ — تردد و مرخصی**: مانده مرخصی از درخواست‌های ثبت‌شده **مشتق** می‌شود (هرگز ذخیره جداگانه که بتواند واگرا شود)؛ درخواست بیش از سهمیه سالانه مسدود می‌شود (مرخصی بدون حقوق بدون سقف)؛ روزهای کاری بدون تقویم تعطیلات رسمی محاسبه می‌شوند (محدودیت شناخته‌شده).
- **ماژول ۴ — حقوق و دستمزد**: موتور محاسباتی کامل سالانه با پروریشن روزهای کارکرد، عدم پرداخت به نیروی جداشده، و قفل دوره‌های نهایی/پرداخت‌شده.
- **ماژول ۵ — عملکرد**: ثبت و ویرایش اهداف (OKR/KPI).
- **ماژول ۶ — آموزش**: ثبت‌نام واقعی سمت سرور با جلوگیری از ثبت تکراری و مهر زمانی واقعی.
- **ماژول ۷ — چک‌لیست‌ها**: تغییر وضعیت آیتم‌ها با مهر تاریخ جلالی واقعی و ماندگاری.
- **ماژول ۸ — تحلیل و داشبورد**: همه شاخص‌ها از داده زنده محاسبه می‌شوند؛ قیف استخدام از رکوردهای واقعی کارجویان ساخته می‌شود؛ شاخص‌های مالی برای نقش‌های غیرمجاز **حذف (null)** می‌شوند و در UI با «—» نمایش می‌یابند.
- **اتوماسیون‌ها و دستیار صوتی**: اجرای اتوماسیون فقط با نقش مدیر منابع انسانی **و تأیید صریح کاربر** (`confirm: true` / دیالوگ تأیید) ممکن است. اتوماسیون «مرخصی‌ها» فقط گزارش می‌دهد و هیچ تأییدی انجام نمی‌دهد؛ «غربالگری» فقط بر اساس امتیازهای موجود بازده‌بندی می‌کند؛ «حقوق» فقط پیش‌نویس‌ها را نهایی می‌کند.

## ۴. راهنمای نصب و راه‌اندازی محلی

### الزامات
- Node.js نگارش ۱۸ یا بالاتر
- **اختیاری:** کلید `GEMINI_API_KEY` در فایل `.env` (الگو در `.env.example`). بدون آن، سامانه با بازگشت محلیِ برچسب‌دار کار می‌کند و هیچ پاسخی را به دروغ به Gemini نسبت نمی‌دهد.

### دستورات اجرا
```bash
# ۱. نصب پکیج‌ها
npm install

# ۲. اجرای سرور توسعه (پورت ۳۰۰۰)
npm run dev

# ۳. بیلد نسخه نهایی پروداکشن
npm run build
npm start
```
پس از اجرا، سامانه در آدرس `http://localhost:3000` در دسترس خواهد بود.

### ریست داده و آزمون‌ها
```bash
# ریست به داده اولیه: حذف اسنپ‌شات و اجرای مجدد سرور
rm data/hrms-store.json

# سوئیت رگرسیون اصلاحات محصول (۴۷ آزمون؛ روی داده تازه اجرا شود)
node scripts/product_fix_verification.cjs

# آزمون سرتاسری API
node scripts/strict_e2e_test.cjs
```
